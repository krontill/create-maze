### Key Implementation Decisions

1. Row-major traversal (r=0..height-1, c=0..width-1): processes cells sequentially,
   making the north/east decision purely local — O(1) per cell.

2. Direction priority: both north (r-1) and east (c+1) are checked per cell.
   When both are in-bounds, random() < 0.5 picks between them.
   When only one is in-bounds, that direction is used deterministically.
   Top-right corner (r=0, c=width-1): no valid neighbour; cell is marked but no passage
   is carved. The entry/exit openings from createGrid ensure the 1×1 edge case works.

3. No auxiliary data structures: unlike DFS or Prim's, Binary Tree needs no visited
   array or stack — pure O(1) extra space beyond the grid.

4. PRNG: createRandom(seed) used for reproducibility; same seed always produces the
   same maze (verified by determinism test).

5. Algorithm characteristic: produces a strong diagonal bias — the top row is always a
   single horizontal corridor (all east carvings) and the right column is always a
   single vertical corridor (all north carvings). The description in the demo card
   calls this out explicitly.
