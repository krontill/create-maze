### Key Implementation Decisions

1. **Algorithm choice — north/east bias**
   The canonical Binary Tree algorithm picks randomly between two directions for each cell. North and east were chosen so the top row and right column become fully-open corridors — the distinctive visual signature of the algorithm.

2. **Edge-case handling**
   - Top row cells (r = 0): can only carve east.
   - Rightmost column cells (c = width-1): can only carve north.
   - Top-right corner (r=0, c=width-1): no valid neighbour; cell is marked as a passage but no extra carving is needed (the entry/exit openings from `createGrid` maintain connectivity for 1-cell edge cases).

3. **O(1) auxiliary space**
   Unlike DFS (stack) or Prim's (frontier set) or Kruskal's (union-find), Binary Tree needs no auxiliary data structure beyond the output grid, making its space complexity truly O(1) — the smallest of all four algorithms.

4. **Strategy pattern**
   `BinaryTreeGenerator` implements `IMazeGenerator` (the same interface as the other three algorithms) and is registered in the `GENERATORS` map in `src/index.ts`.  The public `generateMaze()` API required no changes.

5. **Determinism via seeded PRNG**
   Uses the existing `createRandom(seed)` utility so the same seed always produces an identical maze.

6. **Tests**
   Added `Algorithm.BINARY_TREE` to the shared `ALGORITHMS` array in `tests/index.test.ts`. All 9 shared behavioural tests (correct dimensions, only 0s/1s, open entry/exit, fully connected, deterministic, different seeds differ, 1×1, 1×N, N×1, graph format) are exercised against Binary Tree automatically.
